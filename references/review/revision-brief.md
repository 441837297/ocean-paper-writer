# Revision Brief

## Purpose

A Revision Brief is the short, confirmed interface between scientific strategy and manuscript prose. It records the intended change for one bounded unit. Once confirmed, it is a closed scientific contract, not a loose writing suggestion, a second project plan, an issue dump, or final English prose.

Use it for established-manuscript revisions, feedback, and any candidate revision that needs independent verification. A brief is usually 300–800 Chinese characters, or the equivalent concise length in another language.

## Template

```markdown
## Revision ID
REV-<unit>-<number>

## Status
Frozen

## Unit
<section, paragraph, figure, or response item>

## Current function
<what the old text currently does>

## New function
<what the revised unit must accomplish>

## Keep
<facts, wording, logic, or connections that must remain>

## Remove / supersede
<claims, metrics, wording, or emphasis to delete or prevent from returning>

## Verified new evidence
<verified results, figures, or numbers to add; or none>

## Argument sequence
<the intended order of claims and evidence>

## Claim boundary
<what the new text must not claim>

## Connection
<how it joins the adjacent text>

## Acceptance criteria
<conditions for Verify to return PASS>
```

## Analysis Task

When Strategy cannot make a sound writing decision from the available evidence, create this compact task instead of guessing:

```markdown
## Question
<scientific question to resolve>

## Required analysis
<calculation, comparison, or inspection>

## Input
<necessary data or material>

## Expected output
<required number, table, figure, or finding>

## Decision criterion
<how the output changes the Revision Brief>

## Do not infer
<what this analysis cannot establish>
```

Return the result to Strategy, update the brief if needed, and obtain confirmation before Prose.
