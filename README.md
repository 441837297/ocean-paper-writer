# Ocean Paper Writer

用项目证据和真实参考论文，在同一会话完成海洋科学论文的起草、修改、润色、按需审查、反馈回复与投稿文字。写作与审查统一使用 `ocean-paper-writer`，无需独立 Reviewer，也不默认每次写后必审。

## 怎么使用

给出当前任务、目标文字或项目入口即可。任务不清时，助手会建议当前最值得做的一件事，说明必要材料和交付，只问阻塞问题；任务明确时直接执行。

- **普通写改**：“润色这段英文，保留科学含义。”使用目标文字、必要上下文和相关项目约定，不额外读论文或写作指南。
- **参考深度润色**：“从项目论文中找相关 Discussion，学习其证据组织，再修改我的段落。”实际阅读有关原文，不把参考论文的结果移植为本项目结果。
- **对照审查**：“对照相关目标期刊论文检查这一节，只给重要问题和最小修复。”可局部或全文；单纯数字、术语一致性检查使用相关项目材料即可。
- **审稿回复**：“根据这条意见、已接受决定和实际改文拟回复。”区分已做、拟做与未做，不为回信声称完成不存在的工作。

默认在对话中交付，只有用户授权才写入文件。检查请求不自动变成改稿请求，润色不自动修改上游项目材料。

## 项目材料与参考论文

项目任务先从可用的 `AGENTS.md`、项目说明或现有材料确认当前稿和有效决定，按任务读取相关正文。`01` 对应问题、证据及范围；`02` 对应数据、方法与统计；`03` 对应术语、结构与图件；`04` 是当前稿；`05` 是反馈及已接受决定。项目写作、润色及相关审查必须核对并遵守适用的 `03` 术语，其他材料按任务需要读取，具体触发见 [SKILL.md](SKILL.md)。

这些编号表示角色，不要求改名、补齐目录或全读。已读且仍有效的材料可以复用；文件名和索引不能代替实际内容。缺材料时说明未核实事项，冲突按项目权威规则处理，优先级不清时询问。无项目的独立文本不要求 `01–05`。

参考文献来自实际项目文件夹或用户指定、上传的真实论文，不要求目录名为 `reference`。索引和笔记用于定位原文，不能代替核查。科学判断以实际证据为依据，参考论文不能覆盖本项目定义和有效决定。期刊格式要求需核对当前官方要求，写作借鉴使用真实论文，不套固定“顶刊规则”。

## 小入口与按需资源

核心 `SKILL.md` 负责引导、材料选择与科学边界。普通写改不加载下面的专项资源，也无需角色交接、冻结简报或等待 PASS。

| 资源 | 仅在何时使用 |
|---|---|
| [文献阅读与对照](operations/literature.md) | 深入学习、多篇比较、阅读笔记或委派阅读 |
| [审稿回复](operations/response.md) | 起草、修改、检查回复信 |
| [文档交付](operations/document-delivery.md) | Word、修订记录与最终文件核验 |
| [最小建档参考](templates/project-starter.md) | 用户要求初始化或整理未建档项目 |

专项材料从旧版 Git 文件中提炼，保留可追溯原文、回复与改文对应、引用域及公式保护等经验；不恢复章节教程、通用润色词表、强制阶段模板或期刊规则库。

单篇局部核查通常直接读；多篇、大量材料或需要独立判断时，在环境支持且允许委派的前提下可使用子代理。子代理回传相关原文、位置及边界，主模型综合；不用子代理也能完成任务，不固定模型或新增强制审批步骤。

真实范例优先保留在项目中，跨项目收录须经用户确认，不复制第二套素材库。资源存在于目录中不等于每次加载；实际读取仍由当前任务决定。

## 本地与 Web

本地按客户端方式调用 `$ocean-paper-writer`，安装说明见 [INSTALL.md](INSTALL.md)。由 Magpie 管理时先修改主库再同步，避免仅修改客户端副本。

Kimi Code 与 Web 使用同一核心逻辑。Web 需提供实际可访问的项目文件，电脑路径本身不能提供文件访问；需要时可将技能及适用资源一并上传。文件读取或 ZIP 上传成功不等于原生安装，也不等于所有约束均已执行。

本地附带 [操作资源](scripts/README.md) 和两个可选 Word 回复信模板，仅在实际文件操作时使用。Web 分发可不含本地脚本，文件交付能力取决于当时可用工具；文字写作不依赖这些脚本。
